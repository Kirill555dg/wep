# 3. ОБЩИЕ ПОЛОЖЕНИЯ
Настоящие указания содержат требования к порядку выполнения и
оформления курсовых работ (КР) по дисциплине «Разработка клиент-
серверных приложений» в соответствии с Инструкцией по организации и
проведению курсового проектирования (СМКО МИРЭА 7.5.1/04.И.05-18).

## 3.1. Цели и задачи курсовой работы
Основной целью курсовой работы является формирование и закрепление
компетенций путем практического использования знаний, умений и навыков,
полученных в рамках теоретического обучения, а также выработка
самостоятельного творческого подхода к решению конкретных
профессиональных задач.
Курсовая работа должна соответствовать следующим требованиям:
1. Соответствовать установленной структуре, а по содержанию – заданию
на ее выполнение.
2. Быть выполненной на достаточном теоретическом уровне.
3. Основываться на результатах самостоятельной работы (расчеты,
исследования).
4. Иметь обязательные самостоятельные выводы в заключении.
5. Иметь необходимый объем.
6. Быть оформленной в соответствии с установленными требованиями.
Структура и объем курсовой работы:
Курсовая работа как письменная теоретическая работа должна иметь
следующую структуру:
1. Задание на курсовую работу.
2. Титульный лист.
3. Аннотация.
4. Содержание (оглавление).
5. Перечень сокращений (при необходимости).
6. Введение.
7. Основная часть (главы, разделы).
8. Заключение.
9. Список использованной литературы (источников).
10. Приложения (при необходимости, не более 15% от объема работы).
Общий объем КР не должен превышать 50 страниц.

Аннотация (рекомендуемый объем – 1-2 стр.) представляет собой краткое
изложение содержания КР с основными выводами и рекомендациями,
приводятся данные об объеме КР, количестве рисунков, таблиц, приложений,
использованных источников.

В содержании (оглавлении) приводятся наименования структурных частей
КР, разделов и подразделов основной части с указанием номера страницы, с
которой начинается соответствующая часть, раздел (подраздел).

В перечне сокращений, условных обозначений, символов, единиц и
терминов приводятся используемые в КР малораспространенные сокращения,
условные обозначения, символы, единицы измерения и специфические
термины. Если в перечне сокращений отсутствуют специфические термины или
единицы измерения, или условные обозначения, то данный раздел в КР не
включается.

Во введении (рекомендуемый объем – 1-2 стр.) дается общая
характеристика КР:
− обосновывается актуальность выбранной темы;
− определяется цель работы и задачи, подлежащие решению для её
достижения;
− описываются объект и предмет исследования, используемые методы и
информационная база исследования, а также кратко характеризуется структура
КР по разделам.

Основная часть (рекомендуемый объем – от 10 до 40 стр.) содержит
материал, необходимый для достижения цели КР. Содержание основной части
должно соответствовать теме, указанной в задании, и полностью ее раскрывать.
Обязательным для текста КР является логическая связь между разделами и
последовательное развитие основной темы на протяжении всей работы,
самостоятельное изложение материала, критический подход к изучаемым
данным, проведение необходимого анализа, аргументированность выводов,
обоснованность предложений и рекомендаций. Также обязательным является
наличие в основной части КР ссылок на использованные источники.


## 3.2. Структура основной части отчета курсовой работы

1. Описание предметной области, для которой разрабатывается
соответствующее ПО, а также обоснование выбора именно клиент-серверной
архитектуры для данной задачи. Дать описание и обоснование выбора
клиентской части. Клиентом может быть: веб-браузер, мобильное приложение,
десктоп-приложение и т.д.
2. Обоснование выбора стека технологий для реализации клиент-
серверного приложения и соответствующего инструментария для разработки. В
зависимости от выбранной темы, в качестве стека технологий могут быть
выбраны технологии, связанные с разработкой клиент-серверного приложения.
Интерфейсная часть построена с использованием некоторых языков,
которые обсуждаются ниже:
HTML: HTML означает язык разметки гипертекста. Он используется для
разработки передней части веб-страниц с использованием языка
разметки. HTML представляет собой комбинацию гипертекста и языка
разметки. Гипертекст определяет связь между веб-страницами. Язык разметки
используется для определения текстовой документации внутри тега,
определяющего структуру веб-страниц.
CSS: Каскадные таблицы стилей, ласково называемые CSS, представляют
собой просто разработанный язык, предназначенный для упрощения процесса
придания веб-страницам презентабельного вида. CSS позволяет применять
стили к веб-страницам. Что еще более важно, CSS позволяет вам делать это
независимо от HTML, из которого состоит каждая веб-страница.
JavaScript: JavaScript — это известный язык сценариев, используемый для
создания магии на сайтах, чтобы сделать сайт интерактивным для
пользователя. Он используется для расширения функциональности веб-сайта
для запуска классных игр и веб-программного обеспечения.
## 3.3. Фронтенд-фреймворки и библиотеки
AngularJS : AngularJs — это интерфейсная среда JavaScript с открытым
исходным кодом, которая в основном используется для разработки
одностраничных веб-приложений (SPA). Это постоянно растущая и
расширяющаяся структура, которая предоставляет лучшие способы разработки
веб-приложений. Он изменяет статический HTML на динамический HTML. Это
проект с открытым исходным кодом, который может свободно использоваться и
изменяться кем угодно. Он расширяет атрибуты HTML с помощью директив, а
данные связываются с HTML.
React.js : React — это декларативная, эффективная и гибкая библиотека
JavaScript для создания пользовательских интерфейсов. ReactJS — это
интерфейсная библиотека на основе компонентов с открытым исходным кодом,
отвечающая только за уровень представления приложения. Его поддерживает
Facebook.
Bootstrap : Bootstrap — это бесплатный набор инструментов с открытым
исходным кодом для создания адаптивных веб-сайтов и веб-приложений. Это
самая популярная среда HTML, CSS и JavaScript для разработки адаптивных
мобильных веб-сайтов.
jQuery : jQuery — это библиотека JavaScript с открытым исходным кодом,
которая упрощает взаимодействие между документом HTML/CSS, или, точнее,
объектной моделью документа (DOM), и JavaScript. Уточняя термины, jQuery
упрощает просмотр и манипулирование документами HTML, обработку
событий браузера, анимацию DOM, взаимодействие Ajax и разработку
JavaScript для разных браузеров.
SASS: это самый надежный, зрелый и надежный язык расширений CSS. Он
используется для расширения функциональности существующего CSS сайта,
включая все от переменных, наследования и вложенности с легкостью.
Некоторые другие библиотеки и фреймворки: Semantic-UI, Foundation,
Materialize, Backbone.js, Express.js, Ember.js и т. д.
Серверная часть: относится к разработке веб-приложения или веб-сайта
на стороне сервера с упором на то, как работает веб-сайт. Он отвечает за
управление базой данных через запросы и API с помощью команд на стороне
клиента. Этот тип веб-сайта в основном состоит из трех частей: внешнего
интерфейса, серверной части и базы данных.
Серверная часть построена с использованием некоторых библиотек,
фреймворков и языков, которые обсуждаются ниже:
PHP: PHP — это серверный язык сценариев, разработанный специально
для веб-разработки. Поскольку PHP-код выполняется на стороне сервера, он
называется языком сценариев на стороне сервера.
C++ Это язык программирования общего назначения, широко
используемый в настоящее время для соревновательного программирования. Он
также используется в качестве внутреннего языка.
Java: Java — один из самых популярных и широко используемых языков и
платформ программирования. Он легко масштабируется. Компоненты Java
легко доступны.
Python: Python — это язык программирования, который позволяет вам
работать быстро и более эффективно интегрировать системы.
JavaScript: Javascript можно использовать как язык программирования
(внешний и внутренний).
Node.js : Node.js — это кроссплатформенная среда выполнения с открытым
исходным кодом для выполнения кода JavaScript вне браузера. Вы должны
помнить, что NodeJS — это не фреймворк и не язык программирования. Его
используют в производстве такие крупные компании, как Paypal, Uber, Netflix,
Walmart и так далее.
Back End Frameworks: список серверных фреймворков: Express, Django,
Rails, Laravel, Spring и т. д.
Другие языки внутренних программ/скриптов: C#, Ruby, REST, GO и т. д.
База данных: база данных представляет собой набор взаимосвязанных
данных, которые помогают эффективно извлекать, вставлять и удалять данные
из базы данных и организовывать данные в виде таблиц, представлений, схем,
отчетов и т. д.
Oracle: база данных Oracle — это набор данных, которые рассматриваются
как единое целое. Целью этой базы данных является хранение и извлечение
информации, связанной с запросом. Это сервер базы данных, используемый для
управления информацией.
MongoDB : самая популярная база данных NoSQL, представляет собой
ориентированную на документы базу данных с открытым исходным
кодом. Термин «NoSQL» означает «нереляционный». Это означает, что
MongoDB не основана на табличной структуре реляционной базы данных, а
предоставляет совершенно другой механизм хранения и поиска данных.
Sql : язык структурированных запросов — это стандартный язык базы
данных, который используется для создания, обслуживания и извлечения
реляционной базы данных.
В силу того, что при промышленной разработке ПО необходимо обес-
печить проверку работоспособности приложения, необходимо, либо вно-
сить данные в базы данных в ручном режиме, либо воспользоваться раз-
личными библиотеками, такими как Faker JS, fony, Casual, Fake Store API и
т.д. В рамках данной курсовой работы для демонстрации работоспособности
приложения можно воспользоваться реальными данными или сгенерировать
тестовые данные, с использованием вышеприведённых библиотек.
Крайне желательно использовать именно NoSQL подход. В случае, если
выбран SQL решение, то необходимо обосновать использование именно SQL
СУБД.
Рекомендуется использовать такие популярные стеки как:
− Стек MEAN: MongoDB, Express, AngularJS и Node.js.
− Стек MERN: MongoDB, Express, ReactJS и Node.js
− Django Stack: Django, python и MySQL в качестве базы данных.
− Rails или Ruby on Rails: использует Ruby, PHP и MySQL.
− Стек LAMP: Linux, Apache, MySQL и PHP.
Если в названии выбранной темы указаны конкретные средства и
технологии, то необходимо использовать именно их и провести краткий анализ
данных технологий.
Приветствуется использование сторонних библиотек, которые не указаны в
данном списке. Любая стороняя библиотека, используемая в проекте, должна
быть обозначена в тексте работы и должна быть дана краткая её
характеристика.
Исходя из выбранного или предложенного стека технологий, осуществить
выбор и его обоснование облачной PaaS платформы (например, Heroku, Google
App Engine, Cloudify и т.д.) для дальнейшейго развёртывания приложения.
Обосновать выбор системы версионного контроля для данного проекта.
Рекомендуется использовать связку Git, GitHub и Heroku, но будьте
внимательны, что в зависимости от выбранных технологий, могут встречаться
ограничения платформы Heroku. Например, надстройка mLab Heroku, которая
активно использовалась разработчиками, отключена 10 ноября  г. Поэтому
можно продолжать использовать Heroku с развертыванием MongoDB, но уже не
в качестве надстройки Heroku.
Дать описание архитектуры системы и реализацию многослойного клиент-
серверного приложения (трёхуровневая модель архитектуры клиент-серверного
приложения - клиентские приложения, сервер приложений и сервер баз данных)
с использованием выбранного стека технологий. Описать процесс разработки
клиентской и серверной частей. В обязательном порядке должна быть
реализована поддержка серверной частью процессов входа в систему и
хранение информации о пользователе разработанной системы.
Проект должен быть подвергнут версионному контролю и развёртыванию
в бесплатной облачной PaaS платформе, например Heroku. Проект должен быть
также размещён в репозитории на GitHub, ссылка на который должна быть
продемонстрирована в отчёте. В тексте работы продемонстрировать процесс и
привести скриншоты выполнения нескольких коммитов в репозитории проекта
и описать процесс загрузки (деплоймента) приложения в облачный PaaS сервис.
Например, даже если вами выбрана тема с разработкой клиент - серверного
приложения с API, то описываем процесс разработки серверной части API с
соответствующей базой данных и реализуем простейший графический
интерфейс (frontend) для демонстрации работоспособности API, весь этот
проект размещаем, например, в репозитории GitHub и развёртываем в Yandex Cloud или аналогичных сервисах.
Провести проверку функционирования основного минимально
работоспособного продукта. В зависимости от задачи, либо воспользоваться
реальными данными, которые могут быть занесены вами вручную или
получены посредством стороннего API, либо сгенерированы с использованием
сторонних библиотек. Например, в случае разработки почтового сервиса для
отправки сообщений с использованием Mailgun API, содержимое письма,
отправителя и т.д. можно ввести вручную.

В заключении (рекомендуемый объем – 1-2 стр.) логически
последовательно излагаются теоретические выводы и/или практические
предложения, которые сформулировал студент в результате выполнения КР.

Список использованных источников отражает степень охвата материала
при решении поставленной задачи.

В приложения (при его необходимости) помещается вспомогательный
материал (при его наличии), который при включении в основную часть работы
осложняет её восприятие (таблицы вспомогательных цифровых данных,
инструкции, методики, формы отчетности и других документов и т.п.).
